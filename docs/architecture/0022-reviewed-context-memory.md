# ADR 0022: Reviewed context summaries, model budgets and delivery cursors

Status: Accepted for v0.21.0. Extends ADRs 0002/0017. Existing routing, collection, retry, roster, deletion and provider contracts remain authoritative.

## Explicit summaries and original evidence

Authenticated `POST /api/rooms/:roomId/context-summaries` accepts a UUID, exact reviewed workspace revision, retained thread ID, 1–50 distinct completed source IDs, title, overview, disagreement notes and open-question notes. The last three text fields preserve exact whitespace/Unicode and must contain non-whitespace text; the human can explicitly state that a question or disagreement has not been assessed. Sources must belong to the reviewed thread/workspace and be complete. Failed, refused, partial, interrupted and cancelled output cannot become summary evidence. Application-owned identity, source versions, hashes and decision metadata cannot be supplied by the caller.

One SQLite transaction records the human-reviewed summary, ordered source ledger and audit event. Each source retains its stable identity, original author label, sequence/type, SHA-256 of the canonical JSON string for the exact body (preserving Unicode code-unit distinctions) and an attributed excerpt. Sources up to 320 Unicode code points remain complete; larger sources retain their first/last 160 code points with an explicit omission notice. Accepted coordinator ask/finish decisions retain their exact original routing/reply links, separate from source prose. The original complete message and decision remain authoritative and retained; summary excerpts never replace them in storage. Notes and excerpts render as escaped text.

There is no autonomous model summary, semantic agreement classifier, or promise that a human synopsis is complete. Separate disagreement/open-question notes, an excerpt for every source, original author/decision links and explicit elision notices preserve competing evidence instead of representing a merged opinion as consensus. Provider guidance requires preserving these differences, attributing unresolved claims, acknowledging incomplete evidence, and asking the human for originals when the summary is insufficient. Model compliance is not guaranteed. An exact original is always available through its retained source link until deletion.

A workspace retains at most 100 summaries; each record is bounded to 64,000 characters. Summaries are immutable records; another review creates a new record. Replay of the same UUID/validated command returns the original without mutations or another record, even after the capacity limit; changed content or collision with a message command conflicts. A stale review, invalid source, capacity failure, archive or shutdown rejects before writes. Creating/reading a summary invokes no provider, consumes no turn and never resumes paused/stopped work. Paused/stopped workspaces can retain local reviews; archives are read-only.

## Authorized original retrieval and selection

`GET /api/rooms/:roomId/context-summaries/:summaryId/sources/:messageId` enforces the existing local session/Host/Origin boundary, exact workspace and summary membership, retained thread, complete status, original author/type/sequence and matching body hash before returning the exact original. Foreign, unselected, deleted or inconsistent sources cannot be expanded. Retrieval is read-only, including in archives, and makes no provider call. Original inspection/copy remains an explicit user action; provider prose and summary decision links cannot retrieve a source or grant routing authority.

An ordinary human Question (including the root of a relay or discussion) may explicitly select `{summaryId, sourceIds}`. The application removes only that summary's originals from the otherwise relevant submitted context, substitutes the frozen review/ledger and includes checked full originals. Other relevant retained history stays; later messages are not fetched into the submitted snapshot. A reply target covered by the summary automatically retains its exact full body. A summary may explicitly supply previously reviewed sources to a new thread in the same workspace. Updates/interjections reject summary controls. No generated action can select a summary or expand a source.

Snapshots carry an independent copy of review notes, source versions/decision links and retrieved IDs. New questions use current instructions/roster bindings; original retries, closed-set synthesis, updated synthesis, relay/peer/coordinator continuations and bounded corrections retain the submitted summary and instruction/participant binding. Checked originals are fully attributable and cannot be trimmed. Sibling first answers share the same submitted base and never acquire a sibling answer channel. Different reviewed model budgets may omit different older base-history messages in their own delivery snapshots, while preserving that isolation.

## Reviewed model text budgets

Participant configuration optionally records `{maxCharacters, overflow}` with its exact frozen provider/model/endpoint revision. Limits are integers 4,096–262,144. `reject` blocks an oversized invocation; `trim_oldest` omits the oldest unprotected base-history messages until the complete application system/user strings fit. Character counts are JavaScript string characters, matching existing application text limits. They are not provider tokens, a model capability catalog or a guarantee about a native context window; protocol/schema overhead and provider input/output token limits require a separate human review. No invented model capacities, token conversion, new dependency or capacity-probing provider request is used.

Changing provider, model or endpoint clears an omitted legacy policy; the UI clears its review immediately on those edits. A same-model older caller that omits this field preserves it; explicit null restores legacy behavior. Names/roles/limits and new questions do not overwrite a submitted policy. Configuration history retains full policy revisions. Without a configured policy the existing 64,000-character snapshot check and original behavior remain. Summary text/ledger also count toward that shared snapshot limit; users can explicitly compact long history, while oversized mandatory context still fails.

Before a provider invocation or turn claim, fit the exact common application prompt. Protect objective/instructions/roster and summary facts, current/root question, exact reply target, explicitly retrieved originals and every collected answer. Do not cut source strings, instructions, summary notes, disagreement/open questions or eligible answers. Record exact omitted IDs and measured prompt length in a separate frozen delivery snapshot; the submitted base, bodies and closure stay exact. Provider/UI/inspection/export disclose omissions. Too-large protected context fails the job visibly before provider invocation, attempt/turn claim or cursor advancement; failed recipient eligibility and workflow barriers remain unchanged. Changing current settings cannot fix an original retry's frozen budget; ask a new reviewed question.

A retry reuses the prior fitted message set, summary and original policy, including omissions; it cannot silently restore or trim another source. Synthesis retry retains exact included answers even after a late answer. A new separate updated synthesis retains the original summary/binding and newly authorized completed answers. Its model budget is independently checked; a capacity failure cannot relabel completed answers or rewrite an existing closure. Routing reply validation uses the actual supplied coordinator context, while peer/continuation bases preserve the submitted workflow context.

## Local delivery cursors

A successful local dispatch transaction records a monotonic delivery number and the latest cursor for that exact participant/thread: frozen provider/model, job/snapshot, source sequence, exact full-body IDs, summary reference IDs, retrieved IDs, budget omissions and preparation time. No cursor advances for queued/paused work, UUID replay, a budget rejection or failed database write. Provider failures may retain a locally prepared cursor; this is not an acknowledgement of remote receipt, reading, comprehension or retention. Older snapshots do not acquire invented cursors.

Cursors never suppress source history, change scheduling, authorize retrieval or start work. Source sequence identifies the frozen snapshot, not proof that every preceding message was read. Inspection shows the original binding and current attempt outcome separately. Restart retains the saved records, pauses unfinished work and never replays it. Retired participants retain historical records under the existing identity rules.

## Deletion and failure handling

Thread deletion finds dependencies through ordinary snapshot messages and summary source IDs. Cancel/abort dependent work before redacting. If any original is removed, clear the summary's title/prose/excerpts/decision copies, retain a non-content invalidated record, and tombstone its command UUID. Redact copied summaries in surviving snapshots, record deleted source IDs and reject affected retries/new selections. Remove cursors owned by a deleted thread and redact affected source links in surviving cursors. Whole-workspace deletion removes these local records. Already submitted provider data, text incorporated into surviving answers and external exports remain outside logical deletion guarantees.

Native form controls retain composer and review drafts. Summary saves have a fifteen-second client bound; a stale or unknown acknowledgement blocks another save until explicit Refresh/review. Refresh observes a previously saved UUID rather than replaying an unknown command. Source reads have a five-second bound, disclose failures and never repeat automatically. Other views reconcile revisions without changing drafts or chosen threads. Invalidated selected summaries visibly block Send until the user selects a valid review or full history. Archived inspection is read-only.

## Validation and remaining scope

Meaningful source/service/protocol tests cover exact source bodies/hashes/attribution/decision links, strict scope/status/body bounds, immutable reviews, stale/UUID replay, SQLite write rollback, retention limits, explicit compaction/expansion, sibling isolation, protected fitting/omissions, pre-invocation failures/turn accounting, current-versus-frozen policies, retries/late synthesis, all five native envelopes, cursors, disk restart and deletion/redaction. Five isolated Chromium regressions cover review/source copying, keyboard/native controls, safe hostile text, both narrow themes, drafts/cross-view refresh, model budgets, context/cursor inspection, stale saves/lost acknowledgements, real service restart and source deletion. Protocol servers are inert loopback fixtures with blank cloud keys.

Exact completed counts/commit/tree/CI evidence belong in Recovery. Browser discovery is not a pass. Native token/capability catalogs, semantic summary generation, general rollover/pending-work restoration, broad large-history pagination, attachments/restricted access control, correction/supersession, packaging and live credentialed/model verification remain separate original requirements. No schema/runtime/dependency/license/routing-authority change or version 1 release is included.
