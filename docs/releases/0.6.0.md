# v0.6.0 — Search, thread names, and workspace archives

Search your workspaces and conversations, rename a thread without interrupting its work, and move a finished workspace into an archive while keeping its full history. Restore it when needed; execution resumes only when you explicitly choose Resume.

## Changes

- Add workspace name/objective search and Active, Archived, and All workspace views.
- Search the selected workspace's thread names and retained message text, including streamed text, with literal matching, bounded plain-text previews, clear controls, and no-match states.
- Add thread rename/cancel controls. Names update across views and in exports while IDs, messages, reply targets, frozen context, and pending work remain intact.
- Add named archive/restore confirmations in Settings and archived conversations. Archive requires pending work and workspace probes to finish or stop; paused or blocked obligations still count.
- Preserve conversation data, participant revisions, and used turns. Archived workspaces support reading, search, inspection, export, restoration, and whole-workspace deletion, with other changes and provider invocations blocked.
- Preserve open drafts across search and cross-view archive updates. Archived controls stay disabled; restoring leaves the workspace paused and never replays cancelled or failed work.
- Retain an archive-only application across a real service restart without creating another welcome room. Existing legacy room documents remain readable.
- Include archive state and current thread names in Markdown exports alongside stable IDs and original invocation/author settings.

## Upgrade

Stop the local service, update the checkout, and rebuild:

```sh
git pull --ff-only
npm ci
npm run build
npm start
```

Use Node 26.10 or newer in the 26.x series, or Node 24.15 or newer in the 24.x series. The optional archive field requires no database schema change; absent/null means open. Existing participant configuration history and snapshots stay intact. Interrupted-work recovery still requires explicit continuation. An archive is retained application data, not a separate backup.

## Limits

Search covers workspace metadata and the selected workspace's retained room-visible messages already loaded by the client. Global message search, indexing/ranking, pagination, advanced syntax, saved views, bulk organization, and thread archive remain planned. Queries and drafts are not persisted across browser reloads. Restore an archived workspace before editing its threads or configuration; whole-workspace deletion remains available with confirmation. Archiving does not make data private, refund usage, or guarantee recovery from disk loss.
