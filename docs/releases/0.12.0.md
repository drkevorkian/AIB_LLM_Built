# v0.12.0 — Optional bounded code highlighting

## Behavior

Code stays plain until you choose **Highlight code** on an explicitly labeled JavaScript, TypeScript, JSON, or Python block. The native toggle works with Enter and Space, affects only that block, and retains the choice across theme changes. Source/formatted toggles and reload return to plain code. Fence aliases are case-insensitive; unlabeled, indented, and unsupported code stays plain without language guessing.

Highlighting colors approximate lexical categories using application-owned spans and escaped text. It never executes code, generates HTML, loads grammars, or fetches resources. Each block is bounded to 20,000 UTF-16 code units, 1,000 lines, and 2,000 coalesced token runs. Above a limit, complete plain code and an explanatory notice remain available; code is never truncated. Copy code keeps the complete parsed code, and original message copies, source, search, exports, and frozen provider context are unchanged.

Streaming remains literal until the attempt ends. Highlighting a failed partial answer cannot complete it or enable replying. Archived workspaces allow reading and copying without room changes or provider calls. Existing footnote navigation, safe links, escaped HTML, unloaded image placeholders, and formatter failure recovery remain available.

There are no dependency upgrades, runtime-range changes, database migrations, license grants, or package publishing changes. This remains a 0.x release: every README checklist item must be fully implemented and validated before version 1.

## Validation and limits

Nine added highlighting checks bring the engine/service/provider/rendering suite to 200 tests. Three added isolated Chromium flows bring browser coverage to 44 tests. Required gates include type checks, formatting, production builds, production dependency audit, and both full suites. CI checks Node 24.19.0/26.10.0 on Linux, Windows, and macOS, with Chromium under both runtimes on Linux. Exact completed results and local browser limitations belong in `LLM_Recovery_Prompt.md`.

Coverage includes explicit fence aliases, prototype names, exact token text, unfinished/hostile syntax, Unicode, resource boundaries, escaped rendering, per-block keyboard toggles, complete fallback, narrow scrolling, archive/reload, exact copying and provenance, synthetic stream completion/failure, and token-color contrast in both themes. Protocol fixtures use loopback HTTP without cloud credentials or installed models.

This is a lexical aid, not syntax validation or a full parser: regex literals, template interpolation, Python prefixes, and contextual semantics are approximate. Additional language families remain unsupported. Resource limits bound highlighting, not all Markdown nodes or history rendering. Broader accessibility/contrast, real assistive-technology and touch-device audits, long-history work, math/diagrams/attachments, credentialed provider verification, and other unfinished README items remain open.
