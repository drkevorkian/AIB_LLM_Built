# v0.21.0 candidate — Reviewed context memory

This five-item development candidate awaits complete cross-platform/browser validation and publication. Main remains verified v0.20.0; the five original section 9 requirements remain unchecked until validation passes.

Create an explicit human-reviewed context summary from completed original messages and coordinator decisions. Each summary retains source/author/decision links, exact body hashes, attributed excerpts, and separate disagreement/open-question notes. Originals stay complete and can be retrieved and copied explicitly when a synopsis is insufficient. Select a review and checked full originals for a new question; its summary, instructions and model bindings remain frozen through retries and workflow continuations. Saving/reading a review invokes no model and consumes no conversation turn.

Configure a reviewed application prompt text budget for the exact participant model. Choose rejection or visible oldest-history omissions. Instructions, current/root tasks, reply targets, summary notes, checked originals and collected answers are protected. Recorded counts cover complete application system/user text, not native tokenization, capability discovery or provider protocol overhead. Review the provider's input/output limits separately. Too-large protected context fails before invocation or turn use.

Inspect per-participant/thread delivery cursors to see the exact locally prepared bodies, summary references, originals and omissions. They do not establish remote receipt or comprehension, suppress sources, or dispatch work. Restart retains records without replay; deleting original sources redacts and invalidates dependent summaries/context and blocks their reuse. Stale reviews and lost acknowledgements require explicit refresh while retaining drafts.

Validation results and exact application/publication evidence are recorded in `LLM_Recovery_Prompt.md`. The candidate adds 34 meaningful source/service/native-envelope regressions and five isolated browser flows. Final exact counts must come from completed checks; discovery does not validate a browser flow. All original checklist text/order and the version 1 gate remain. Native capabilities/token budgets, automatic semantic summaries, full context rollover, attachments, restricted access, broad accessibility/security/packaging and credentialed provider/model checks remain open.

See [ADR 0022](../architecture/0022-reviewed-context-memory.md). No dependency/runtime/schema migration, license grant, real provider call or npm publication is included.
