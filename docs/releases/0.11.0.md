# v0.11.0 — Safe footnote navigation

## Behavior

Formatted messages now support footnote references and exact backlinks. Labeled buttons work with Enter and Space and move focus within their own message. Repeated references and identical or colliding labels in different messages retain separate targets. IDs remain stable when switching source/formatted views; navigation never changes the URL, fragment, history, thread, or workspace.

At most 100 notes and 300 references per message receive navigation controls. Above either bound, the notes remain readable with a notice and inert reference labels. View source and Copy message retain the complete original body. Streaming remains literal; completed and failed partial answers can format without changing their status. A failed formatter still exposes original footnote source and copying.

Ordinary authored fragments and relative links remain blocked, even when they name a known footnote ID. HTML stays escaped, image references never load resources, HTTP(S) links keep protected new-tab behavior, and code/tasks remain inert. There are no dependency upgrades, runtime-range changes, database migrations, license grants, or package publishing changes. This remains a 0.x release: every README checklist item must be completed and validated before version 1.

## Validation and limits

Seven added rendering checks bring the service/engine/provider/rendering suite to 191 tests. Three added isolated Chromium flows bring browser coverage to 41 tests. Required gates include type checks, formatting, production builds, production dependency audit, and both full suites. CI checks Node 24.19.0/26.10.0 on Linux, Windows, and macOS, with Chromium under both runtimes on Linux. Exact completed results and local browser limitations belong in `LLM_Recovery_Prompt.md`.

The thread-deletion flow now explicitly waits for its exact simulated synthesis to complete before checking the enabled reply control. A prior documentation-commit CI run exposed the default five-second assertion timing out; the test continues to require authoritative completion.

Footnote limits bound interactive controls, not total Markdown nodes or long-history rendering. Broad accessibility/contrast, real assistive-technology and touch-device audits, math/diagrams/highlighting/attachments, credentialed live-provider verification, and the other README work remain open. Automated tests use simulation and synthetic loopback HTTP protocols, without paid provider accounts or installed models.
