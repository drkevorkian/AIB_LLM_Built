# v0.10.0 — Resizable and collapsible panels

## Behavior

Desktop navigation and participant panels now have draggable, keyboard-focusable dividers. Left/Right arrows move a divider by 10 px, Shift increases the step to 50, and Home/End select the current bounds. Focus and accessible size descriptions identify the controlled panel. Completed gestures and keyboard changes save widths in this browser. Escape, cancelled/lost pointer capture, and Settings/compact transitions roll back unfinished drags.

Side panels fit smaller desktops while retaining at least 400 px for the conversation. Merely changing viewport size does not overwrite the saved preference. Compact screens ignore those widths and provide Hide/Show navigation and participants. Drafts, selections, and disclosures remain mounted; pending-response status and both Stop controls remain in the conversation. Settings can reset widths and reopen compact panels. Invalid storage uses defaults; unavailable storage leaves usable resizing with an unsaved notice.

## Preserved guarantees

Layout changes do not mutate room records, call a provider, change service defaults, or consume turns. Original messages, snapshots, attribution, grants, queue order/freshness, and the acknowledged-send selection guard remain intact. There are no dependency upgrades, runtime-range changes, database migrations, license grants, or package publishing changes. This remains a 0.x release: every README checklist item must be completed and validated before version 1.

## Validation and limits

Five added isolated Chromium flows bring the suite to 38 browser tests, alongside the unchanged 184 service/engine/provider/rendering tests. Required gates are type checks, formatting, production builds, production dependency audit, and the full suites. CI checks Node 24.19.0/26.10.0 across Linux, Windows, and macOS, with Chromium under both runtimes on Linux. Exact completed results and any local browser limitations belong in `LLM_Recovery_Prompt.md`.

Width preferences are browser-origin local and take effect in new/reloaded views; existing tabs do not synchronize live. Compact collapse state lasts only for the open view. Broader accessibility/contrast and real assistive-technology/touch-device audits, long-history usability, and other README items remain open. No credentialed provider account or installed model is invoked in automated tests.
