# v0.14.0 — Participant removal with retained history

## Behavior

Settings now offers named, exact-ID participant removal, with focused Cancel and keyboard/close cancellation before confirmation. A reviewed workspace revision prevents removing a target after intervening history/settings changes. Applying holds cancellation; a failed or lost response requires closing and refreshing before another review, without automatic repeat.

Removal permanently retires the identity and frees a current roster slot. At most eight current participants, including inactive ones, remain allowed, with at least one active. Replacements start in simulation with fresh IDs and never-reused roster numbers. Removed records and their configuration history remain available read-only. Original messages, author labels, usage, workflows, source snapshots, and exports remain unchanged. Other views preserve drafts and clear unavailable selections/replies; replacements remain unselected until explicitly chosen.

Any pending workspace work, unfinished workflow, connection probe, or finishing request transport blocks removal. Archive restoration and explicit Stop/cleanup follow the existing policies. Removed identities cannot be reactivated, configured, tested, addressed, or substituted by same-named replacements. Retries requiring them fail before reservation/invocation; otherwise eligible retries preserve their original frozen context, including removed observers. New questions omit removed roles/connections from the roster while retaining authorized conversation history.

One existing README checkbox is completed: participant removal with documented historical attribution, workflow, and retention behavior. No checklist entries are added or removed. Version 1 remains blocked until every README checklist entry is implemented and validated.

## Verification and limits

Required gates include locked installation, TypeScript, formatting, full source suites, production builds, production dependency audits, and Chromium on both supported Ubuntu runtimes. CI also verifies both runtimes on Windows and macOS. Exact completed checks/commit/run links are recorded in `LLM_Recovery_Prompt.md`.

Coverage includes exact scope and review revisions, native cancellation, original attribution/context/export, current-slot reuse and stable numbers, inactive/last-active rules, irreversible eligibility, pending-work and cleanup locks, required/observer retries, stale queued data, forced SQLite rollback, restart and legacy labels, generated-ID collision, HTTP session/Host/Origin/method protections, cross-view drafts, narrow themes, and lost successful confirmation responses. Provider fixtures use simulation and isolated data with blank cloud credentials.

Removal retains data and is not a privacy-erasure operation. Retained conversation text and otherwise eligible frozen retries may still send removed participants' prior content to a provider. Whole-workspace deletion owns retained participant-record deletion; external backups, exports, submissions, and disk remnants remain outside this control. Larger current rosters, groups, pagination, full accessibility/retention audits, credentialed provider verification, and other unfinished README work remain open. No dependencies, runtime ranges, database/schema versions, licenses, or provider permissions change.
