# v0.1.0 — Local conversation foundation

This release starts the M1 local simulation milestone. It uses TypeScript throughout, React for the interface, Node 24 for the service, and SQLite for persistent state.

## Available

- A three-column interface with dark/light themes and a responsive narrow layout.
- Room creation, objectives, per-room threads, and three distinct simulated agents.
- Human questions to selected agents; informational updates that invoke nobody.
- Parallel independent answers and all/any/quorum response collection.
- Optional synthesis by a separate agent after the collection barrier.
- Targeted replies linked to their exact message and thread.
- One active generation per agent, four concurrent generations per service, and reserved turn limits.
- Durable queues, frozen context snapshots, and visible streamed/partial messages.
- Pause, resume, stop, explicit bounded retry, and restart recovery.
- Markdown transcript export and an invocation-context inspector.
- Loopback-only HTTP, host/origin checks, local session tokens, strict commands, and safe text rendering.

## Current limits

- Agents are deterministic fixtures, not live LLM connections. No provider keys are requested, no remote calls are made, and no actual reasoning is claimed.
- Participants have fixed roles and models in this version. Editing the roster and enabling autonomous agent-to-agent sends are planned.
- All messages are room-visible. Restricted/private threads are not supported.
- Automatic review rounds, conference queues, and fixed relays are not implemented.
- Attachments, sandboxed execution, context summarization, imports, and backup tooling are not implemented.
- The local browser interface requires the application service to remain running. A desktop installer is not provided.
- A single service owns each data directory. There is no remote multi-user server or multi-worker scheduler.
- Windows and macOS are intended source-run targets; runtime verification for this build was performed on Linux. CI is configured to cover all three platforms.

## Validation

- 22 Node tests cover engine invariants, persistence/recovery, and the HTTP boundary.
- 3 Chromium browser tests cover parallel answers and synthesis, directed replies, context inspection, export, reload, pause/stop, safe rendering, theme switching, and a 390 px layout.
- Strict TypeScript checks and the production client/server build pass.

The remaining checklist in README.md is the implementation backlog. Checked tasks describe completed work; unchecked tasks remain planned.
