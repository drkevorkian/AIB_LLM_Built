# v0.3.0 — Bounded agent discussions

A selected coordinator can now ask one or both peers, collect their independent answers under all/any/quorum, follow up to one exact answer, and finish for the human. This builds on v0.2.0's live APIs and fixed relays. Choose **Agent discussion** in the composer, select its coordinator, set peer rounds and turn allowance, and send the task.

## Changes

- Reserve the entire discussion allowance before starting; count decisions, peer answers, corrections, and explicit retries against it.
- Validate native structured coordinator actions after provider completion, with server-owned identity and exact-message/thread/context checks.
- Keep peer answers independent and routing-looking prose inert. Freeze included answers before coordinator continuation.
- Permit one correction for an invalid completed decision within its allowance. Provider/network failures still require explicit retry.
- Stop a discussion independently, cancel late respondents on finish, release unused reservations, and preserve grants/queues across restart without replay.
- Show coordinator, round/turn progress, blocked explanations, remaining room reservations, accepted actions, prior attempts, and provider usage in the UI/export.
- Give the provider selector a stable accessible label and keep Jump to latest clear of variable-height composers.
- Preserve older room records through an additive empty-discussion backfill and retain v0.1/v0.2 send hashes when the new grant is absent.

## Limits

The selected coordinator has permission to ask peers; peers cannot delegate. Each room still has three participants. Nested delegation, fair conference queues, active coordinator handoff, revised human instructions, attachments/tools, summaries, private threads, desktop installers, and signed-in website transport remain planned.

The coordinator model/server must support native JSON Schema output. A successful greeting connection test does not verify this capability. Unsupported structured requests fail visibly without a fallback.

A completed invalid action can cause one new correction invocation, which may be billed. Provider/network failures are not automatically replayed. Explicit retries may also incur another charge. Remote reconciliation and token/cost budgets remain incomplete; Stop aborts the local request but cannot guarantee that a provider stops processing or billing.

Discussion context and participant bindings stay frozen. Later updates require a new workflow rather than silently replacing context. Any/quorum late answers remain separate; unfinished late work is cancelled on finish. Repeated-question detection compares normalized question/recipient/policy combinations; it does not measure semantic progress.

The README retains the complete target checklist and adds a separate v0.3.0 checklist so narrower implemented guarantees do not incorrectly complete broader planned items.
