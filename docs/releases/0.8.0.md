# v0.8.0 — Coordinator capability tests

## Behavior

Participant settings now offers **Test coordinator** beside the existing greeting connection test. A greeting may succeed on a model/server that cannot provide structured decisions. The new check sends one native structured-output request and reports success only after one valid completed finish decision.

The check sends participant roles and a test prompt, with no thread history or workspace objective. It never asks peers, creates a discussion, stores conversation records, or consumes room turns. It may incur provider charges. The timeout is 30 seconds or the saved participant timeout if shorter.

Simulation results are explicitly labeled. Success names the requested provider/model, configuration revision, and test time. Results are temporary and apply to that configuration at that time. They do not guarantee all future discussions. Edits, other settings actions, reopening, and reload clear the feedback.

Invalid/unsupported output, refusal, incomplete streams, and network errors fail visibly without automatic retry, correction, greeting fallback, or simulation fallback. Use another explicit click after checking the connection.

## Preserved guarantees

An observed CI navigation race is also fixed: choosing **All messages**, including when it is already selected, during send submission or history refresh now preserves that explicit choice. The same guard preserves a newly selected reply/thread and still waits for authoritative refreshed history before enabling another send. The deterministic delayed-refresh regression covers both the refresh and the held-acknowledgment cases.

Probes share participant serialization and the global generation limit. Pending probes block workspace/roster changes and archive. Deletion and service shutdown abort them and reject late completion. Stored history, frozen context, author attribution, workflow grants, turn accounting, Markdown safety, and the acknowledged-send refresh fix remain intact.

Empty-peer output schemas no longer contain an invalid empty enum. Native schemas still restrict nonempty peer grants, and the engine independently enforces finish semantics and routing permissions. This also keeps single-participant discussions' output schemas valid.

There are no dependency upgrades, runtime-range changes, database migrations, credentials in browser results, or package/license publishing changes.

## Validation and limits

The iteration adds 26 service/HTTP/provider-protocol tests and two Chromium flows, plus an archived-control assertion. Required gates are type checks, all 166 service/rendering tests, formatting, the production build, the production dependency audit, and all 30 Chromium tests. CI checks both Node 24.19.0 and 26.10.0 on Linux, Windows, and macOS, with Chromium on Linux for both runtimes. Exact completion evidence is recorded in `LLM_Recovery_Prompt.md`.

Local service checks run on Node 24.19.0. The browser download in the development environment failed with a truncated archive; browser validation therefore runs in CI before advancing main. Do not interpret that failed download as a local browser-test pass.

No credentialed cloud account or installed Ollama model was invoked in automated tests. Account/model-specific smoke tests, browser-session transport, provider capability catalogs, persistent capability records, nested delegation, attachments, and other README TODOs remain open.
