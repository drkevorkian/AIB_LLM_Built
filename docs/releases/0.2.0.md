# v0.2.0 — Live connections and automatic relay

This iteration adds production HTTP adapters for OpenAI, Grok/xAI, Gemini, Ollama, and OpenAI-compatible text-generation servers. Participants can be configured in the app, models can be discovered, and Test connection performs a real short generation through the selected binding. Source-run scripts load an optional local `.env`; keys remain server-side.

Automatic relay supports 1–12 steps, repeated participants, exact reply links, shared initial context, and the default A → C → B → A order. Future hops are reserved before starting, then released only by completed eligible answers. Failure blocks advancement; stop/restart/retry behavior is persisted.

Provider failures are visible and never become simulated answers. Partial streams, refusals, token-limit truncation, and unsupported tool actions cannot complete a response obligation. Reported request IDs and token usage are inspectable and exported with invocation provider/model labels.

## Verification and remaining limits

Engine/service tests, provider-protocol tests, and five Chromium UI tests cover the implemented workflows. Browser coverage includes configuration → connection check → HTTP relay → targeted reply against labeled local protocol fixtures. No cloud provider keys or actual installed Ollama model were available for credentialed live smoke testing in the build workspace. Use Test connection to verify your own provider/model before relying on it.

The adapters are implemented; account/model availability is not claimed as verified. Signed-in ChatGPT/Grok/Gemini website transport remains unimplemented. Arbitrary agent-chosen routing, open-ended conferences, assigned cross-review rounds, attachments, private threads, monetary budgets, encrypted credential storage, and installers also remain planned.

Live generations are not automatically retried. Explicit retry may duplicate provider processing or charges after uncertain acceptance. Stop aborts the local request and prevents later hops; it does not guarantee cancellation of provider billing.

Existing v0.1 rooms and frozen snapshots remain usable through an additive room-field default. New rooms still start in simulation until their participants are configured.
