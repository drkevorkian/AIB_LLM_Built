# v0.16.0 — Versioned workspace instructions

## Behavior

Create or edit exact workspace instructions, retain objective/instruction revisions, and inspect their history in Settings, including archives. Settings rejects an instruction revision changed by another view and retains unsuccessful edits. Clearing instructions creates a revision; name/limit changes alone do not. Pending requests/workflows and connection checks retain editing locks, and restoring archives remains paused.

New questions freeze current instructions, objectives, and participant configurations. Explicit retries and synthesis, relay, and discussion continuations retain their original bindings. Context inspection shows exact frozen instructions or explicit unknown legacy provenance. All five native provider envelopes include the frozen fields. Instructions remain within application permissions and count toward the shared context bound; connection probes omit instructions, objectives, and history. Markdown export includes retained workspace instruction history and invocation revision references. Thread deletion retains workspace instructions, while workspace deletion removes them.

Legacy workspace records preserve their known current settings without inventing missing edits or timestamps. Old snapshots remain unchanged. Older settings clients can omit new fields. There is no database/schema, dependency, runtime-range, permission, or license change. A participant-removal timestamp defect discovered by the full suite is fixed by reusing the removal time in its history record, with a deterministic advancing-clock regression.

Two original README checkboxes are completed: room objectives/versioned human instructions, and applicable human instructions/correct participant revision in context. All 424 entries are preserved; 178 remain open. Version 1 stays blocked until every entry is implemented and validated.
