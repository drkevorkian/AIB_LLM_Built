# v0.15.0 — Provider and workspace concurrency limits

## Behavior

Settings now saves 1–4 managed requests per provider kind across workspaces and 1–4 per workspace. Generations and greeting/coordinator checks share these allowances, the existing four service slots, and each participant's single active request. All defaults remain four. Queued jobs and retries use their frozen provider binding, including after a participant changes its current connection.

Scoped holds leave attempts, messages, turns, and room revisions unchanged while eligible work in other scopes can proceed. Lowering a provider limit drains active work; raising it allows existing authorized queues to progress at the next scheduler pass. Workspace settings retain pending-work/probe and archive locks. Conversation-default saves and Restore defaults preserve provider policy. Legacy payloads remain readable without a schema migration, and omitted fields retain saved limits.

Queue inspection adds workspace/provider occupancy and specific capacity holds, with anonymous numeric occupancy from other workspaces. Settings changes refresh other views while preserving drafts. Native controls validate bounds, retain unsuccessful edits, and show explicit results.

Completion and Stop retain capacity through cleanup. Confirmed workspace/thread deletion preserves its existing immediate local capacity release after commit/abort. Limits count locally managed requests, not remote processing, rate limits, cancellation, or billing.

One original README checkbox is completed: per-provider and per-workspace concurrency limits. No entries are added or removed; 180 of the 424 original entries remain open. Version 1 stays blocked until every entry is implemented and validated.
