# v0.13.0 — Bulk workspace management

## Behavior

Manage workspaces now archives, restores, or deletes up to 25 exact selected workspaces together. Native checkboxes show separate IDs for duplicate names. Literal search and active/archived/all filters clear selections when changed. A named preview lists the exact targets, retained history, consumed usage, pending work, connection tests, and effects. Cancel, Escape, close, and Back to selection abandon the preview before confirmation.

Confirmation commits the entire selection together or leaves every target untouched. A selected workspace with pending work or a connection probe blocks the whole archive. Archive preserves history and usage; restore leaves restored workspaces paused and already active workspaces unchanged. Deletion commits all row removals before aborting selected streams and probes, retaining unrelated work and rejecting late events. Deleting the final workspace stays effective after restart.

Previews expire after five minutes and cannot be reused after selected data/activity changes, cancellation, confirmation, or service restart. Another explicit review is required. A lost confirmation response requires closing and refreshing to inspect actual state, without an automatic repeat. Drafts and the selected conversation stay mounted through picking, cancellation, archive, and restore. Deleting the selected workspace uses the existing selection/empty-state behavior.

Two existing README checkbox items are completed: bulk archive/restore/deletion with scope, previews, and cancellation; and the remaining bulk-deletion part of archive/search/thread-naming management. Original unchecked items are retained. Version 1 remains blocked until every README checklist item is fully implemented and validated.

## Validation and limits

Sixteen new engine/store/HTTP checks bring the service/provider/rendering suite to 216 tests. Four isolated Chromium flows bring browser coverage to 48 tests. Required verification includes locked installation, TypeScript, formatting, production builds, production dependency audit, and full suites. CI checks Node 24.19.0/26.10.0 on Linux, Windows, and macOS, with Chromium on both Ubuntu runtimes. Exact completed checks and local browser limitations are recorded in `LLM_Recovery_Prompt.md`.

Coverage includes read-only previews and cancellation, exact identities, strict bounds, all-or-nothing archive/restore/delete, revision/probe/transport changes, expiration and reuse, tampered returned metadata, active deletion and late events, forced SQLite write rollback, disk restart, unchanged source/history/usage, cross-view reconciliation, native keyboard controls, narrow layouts, and lost confirmation responses. All browser services clear cloud credentials and use simulation or synthetic loopback protocols.

Deletion is logical removal of app records. Provider submissions, exports, external backups, disk remnants, and billing cannot be retracted by this control. Cancellation ends when confirmation starts. Preview metadata is transient and limited to 50 records, not a durable audit or remote-operation reconciliation facility. Thread batches, workspace groups, backups/retention, full accessibility and large-history audits, credentialed provider verification, and the other README work remain open. No dependencies, runtime ranges, database schemas, permissions, or license grants change.
