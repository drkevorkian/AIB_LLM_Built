# v0.9.0 — Participant queue inspection

## Behavior

Each active participant card now has **Inspect queue**. It shows the running generation, numbered queued generations in stored order, source-thread navigation, frozen provider/model bindings, queue/start times, and applicable response deadlines. Specific holds explain paused/archived/stopped workspaces, participant requests/probes, earlier queue entries, shared capacity, turn limits, and elapsed collecting deadlines.

Synthesis and coordinator continuations awaiting answers appear separately under **Response prerequisites**, with the exact all/any/quorum threshold and each recipient's latest outcome. Failed, refused, or interrupted answers do not count as completed. A continuation joins the numbered queue only after its actual response barrier closes. Existing workflow cards continue to explain blocked relays and decisions; the inspector does not invent later jobs.

An observation time and aggregate shared-slot counts identify the snapshot. Connection checks and closing transport iterators count toward occupancy. Updates refresh with existing service events; disconnected/failed reads are explicit and Refresh retries inspection only. Source links preserve the draft and select the exact thread. Thread titles remain literal text, including HTML-like names. Queue details work with narrow layouts and both themes, and retained archives remain readable.

The release also corrects stale v0.7.0 labels in the application header, local session response, and startup banner by sharing one v0.9.0 version value.

## Preserved guarantees

The authenticated activity endpoint is read-only. Inspection does not call a provider, change room revisions/history, consume/reserve turns, expire requests, alter scheduling order, or trigger retries. Scheduling, completion gating, original snapshots, attribution, archive/deletion boundaries, coordinator grants, and the acknowledged-send selection guard remain intact. Global occupancy includes other workspaces without exposing their identities or work records. No dependencies, runtime ranges, database versions, license grants, or npm publishing behavior change.

## Validation and limits

The release adds 18 service/HTTP tests and three Chromium flows: 184 service/rendering tests and 33 browser tests in total. Required gates are type checks, formatting, the full test suites, production builds, and the production dependency audit. CI checks Node 24.19.0 and 26.10.0 on Linux, Windows, and macOS, with Chromium on Linux for both runtimes. Exact verified commits and run links belong in `LLM_Recovery_Prompt.md`.

Per-participant insertion order is visible; global fairness/priorities, reordering controls, pagination, queue timing estimates, and new concurrency policies remain planned. Readiness is a current observation, not a guaranteed start time. Provider timeouts and remote cancellation/billing limits remain as before. Credentialed account/model smoke tests were not run; normal tests use simulation and synthetic protocol fixtures without cloud credentials.
